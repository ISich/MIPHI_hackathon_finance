# Decision Diff Core — стартовый модуль

Содержит **реально работающий** нормализатор и компаратор для ответов СПР. Не содержит веб-интерфейс, DuckDB, автопроверки и фоновый сервис: это задачи других участников команды.

## Быстрый запуск (Windows PowerShell)

```powershell
cd МФПЦ_hackathon_finance
# скопируйте содержимое архива в корень проекта или подключите как пакет
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
python -m pytest -q
python -m decision_diff.cli --before examples/I32554354_other.json --after examples/I32554354.json --out outputs
```

Команда `--before`/`--after` принимает также **папки** с одинаковыми именами JSON-файлов. Для полного датасета задайте соответствующие `RESULTS/BEFORE_MASTER` и `RESULTS/AFTER_BETA`, а `--out outputs`.

Учебный набор имеет *другую схему*. Для него конфигурация `--config teaching`. Имена файлов в учебном наборе различаются; тесты вызывают функции напрямую и сопоставляют данные с `APP_ID = 1001`.

## API ядра

```python
from decision_diff import normalize, compare, normalize_pair
from decision_diff.configs import REAL

before_rows = normalize(before_json, app_id='I32554354', source='BEFORE', config=REAL)
after_rows = normalize(after_json, app_id='I32554354', source='AFTER', config=REAL)
comparison_rows = compare(before_rows, after_rows)
union_rows, comparison_rows = normalize_pair(before_json, after_json, app_id='I32554354', config=REAL)
```

`normalized_rows` содержат `APP_ID, SOURCE, PREFIX, CLASS, SUFFIX, ARRAY_KEY, KEY, PATH, VALUE, ADJUSTED_VALUE`. `comparison_rows` содержат `APP_ID, PREFIX, CLASS, SUFFIX, ARRAY_KEY, KEY, PATH, VALUE_BEFORE, VALUE_AFTER, ADJUSTED_BEFORE, ADJUSTED_AFTER, DIFF_FLAG, CHANGE_TYPE`.

Ключ атрибута: `(APP_ID, PATH, ARRAY_KEY)`. Конфигурация определяет массивы, исключаемые пути и бакеты. В приложении необходимо дать пользователю редактировать/подменять обработчик и его конфигурацию, включая импорт файла `.py`; пример `REAL` — **не зашит в ядро**.

## ВАЖНО: расхождение в учебных материалах

`examples/README.md` говорит, что изменились **5** атрибутов. Но сами JSON и CSV дают **6**: `decision`, `riskSegment`, `TAKEUP_RATE_IP.value`, `TAKEUP_RATE_IP.version`, `limit`, `rejectReasons.DOCS_EXPIRED`. В приложенном тесте проверяется **6**. Числа полного датасета следует получать от исполнения, не подгонять под чужие ожидания.

## Что уже проверяется тестами

1. Строки учебных JSON точно совпадают с предоставленными нормализованными CSV по всем колонкам CSV (сравнение без учёта порядка строк).
2. Сопоставление массивов по ключам, независимо от порядка.
3. Составные ключи (`product_id` + `type`), вектор скоринга по индексу, ключ модели.
4. Разница между `null` и отсутствующим полем.
5. Ошибка при повторяющихся ключах или неизвестном массиве вместо молчаливой порчи сравнения.
6. Отсутствие технических полей в нормализованном результате.

## Ограничения и последующие задачи команды

- Это **библиотека + отладочная CLI**, не готовое решение хакатона. Нужны: `MartAPI`, база/индексы, сегменты, checks, API, UI, логирование и фоновый запуск.
- Один повреждённый JSON или неопознанный массив пропускает **пару целиком**; `issues.json` показывает причину. Это безопаснее, чем тихо пропустить атрибут; в основном приложении такие ситуации необходимо передавать в автопроверку и журнал.
- В примере составной ключ кодируется двоеточием внутри идентификатора элемента, а вложенные ключи соединяются `|`. Если само значение идентификатора может содержать `:` или `|`, нужно перейти к безопасному кодированию ключей (например, escape/length-prefix) по единому контракту.
- Для `value`-массивов одинаковые скалярные элементы дважды приведут к ошибке дублирования; для таких массивов согласуйте политику мультимножества до поддержки новых форматов.
- `float` сериализуется обычным `str()`, что соответствует присланным примерам. Если источник требует точных десятичных сумм, настройте загрузку JSON через `parse_float=Decimal` и согласуйте сериализацию.
- Однотипные хранилища DuckDB не следует одновременно писать из разных процессов. Реализуйте одного writer/разделение результатов по `run_id`.
- Пользовательские скрипты нельзя исполнять как доверенные в том же процессе веб-сервера: нужен изолированный worker и лимиты.

## Зависимости и Git

- `pyproject.toml` оставлен для описания устанавливаемого Python-пакета из `src/`.
- `requirements.txt` устанавливает основной пакет (`-e .`).
- `requirements-dev.txt` добавляет pytest и ruff для разработки.
- `.gitignore` исключает локальные БД, сгенерированные отчёты, кэши и окружения.
- `examples/` намеренно хранится в Git: небольшие фиксированные примеры нужны для воспроизводимых тестов.
- `data/` с полным датасетом не коммитим; держим отдельно в `ЗАДАНИЕ/`.

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
```

### Интерпретация результата

`test_core.py` содержит тесты pytest, а не самостоятельную программу. `pytest` находит функции `test_*`, запускает их, и в случае нарушения утверждения показывает traceback.
