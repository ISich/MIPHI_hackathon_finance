# Frontend в локальном Codex: разбор среды

Источник: пересланный участником диагностический отчёт, не удалённая проверка его Mac этим агентом. Сообщены macOS/Apple Silicon, терминал и чтение/запись файлов, Git, Node 22, npm/pnpm, чистый локальный main с README. GitHub и finance.corca.ru не резолвятся из сессии, gh и интерактивная browser automation отсутствуют.

## Что действительно блокирует

Нужно различить сетевое ограничение sandbox Codex и сеть самого компьютера. Сбой DNS в сессии не доказывает сломанный DNS macOS и не означает, что сайт недоступен всем. Сначала человек повторяет git ls-remote origin HEAD и curl к стенду/registry.npmjs.org в обычном Terminal.app, вне Codex; секреты не выводит. Затем Codex повторяет те же разрешённые проверки с запрошенным через собственный approval-flow сетевым доступом, если такой запрос доступен. Не отключать глобально sandbox, не менять DNS/VPN/файлы hosts и не подменять SSH-ключи без установленной причины и разрешения.

Если обычный Terminal работает, а Codex нет — ограничение среды агента наиболее вероятно; разрешить только необходимые сетевые действия либо выполнять fetch/install/push человеком. Если не работает и обычный Terminal — исследовать сеть/DNS/VPN машины. Ошибку после восстановления DNS не путать с возможной следующей ошибкой SSH/auth.

## Что не является самостоятельным блокером

- gh необязателен: Git работает без него, PR открывается через браузер.
- Отсутствие frontend/package.json ожидаемо: scaffold ещё не создан и стек не утверждён.
- Docs нет в main, потому что PR #1 Draft и не merged; файл не появится от обновления main. Нужна docs/implementation-foundation либо переданный ZIP документации.
- Нет browser automation: человек проверяет интерфейс в Safari/Chrome; build/typecheck/unit tests выполняет Codex. Автоматизированный browser smoke пока не заявляется выполненным.

## Новое поручение Павла

Настроить локальные Playwright Test + Chromium: Codex сможет выполнять browser actions через Node и терминал даже без встроенного browser-tool. Установка на Mac здесь не выполнялась; [полное поручение](handoffs/frontend-codex.md) требует фактический smoke с открытием страницы, fill/click/assertion и screenshot. Начальная диагностическая отметка «browser automation отсутствует» не означает, что её невозможно добавить.

Локальные коммиты/feature PR разрешены; production-сборка и deploy стенда остаются у Павла несколько раз в день по готовности. Локальные build/tests не заменяют deployment. Сообщение №62 приватное и должно быть передано текстом, его содержимое не восстановлено по догадке.

## После восстановления сетевого доступа

В существующей чистой копии выполнить fetch; feature-ветку предпочтительно создавать от актуального origin/main, а ещё не слитые docs читать отдельно через GitHub/локальный ZIP. Если нужны изменения docs в рабочем дереве, договориться с Павлом, чтобы frontend PR не дублировал весь docs PR. Ветка от docs допустима как явно stacked PR с согласованным base и порядком merge, без автоматического переписывания опубликованной ветки. Не коммитить в main и не перетирать чужие изменения. Если сеть пока закрыта, можно передать ZIP docs локально; это не решает установку отсутствующих npm-пакетов — отдельно нужен разрешённый registry или подготовленный кеш/зависимости.

Backend API и dev-proxy адрес пока не подтверждены. Frontend работает на локальном dev-server; только нужные /api запросы направляются на доступный backend после согласования. Никаких серверных/LLM ключей в браузере. До готовности backend — маркированные fixtures по общему контракту, не «настоящие результаты». Стек frontend требуется выбрать перед scaffold, например Vite/React/TypeScript — кандидат, не принятое решение.
