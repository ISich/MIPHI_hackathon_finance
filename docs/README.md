# Документация реализации — СПР / МИФИ

**Статус:** документационная основа для отдельного Draft PR в `ISich/MIPHI_hackathon_finance`, base `main`. Соглашения по стеку и назначение людей ещё ожидаются; приложение не реализовано этим пакетом.

Исходное требование: [PRD 0.3](PRD.md), переданный пользователем без изменения. Все решения о структуре каталогов, интерфейсах платформы, ролях и порядке работ ниже — **предложения A**, не утверждённый стек. Существующие M/C/Q из PRD сохраняются. Детализация не отменяет обязательные возможности.

## Быстрый старт для команды

1. Прочитать PRD §§5–8, 14 и [разделение на четверых](team.md).
2. Назначить людей на D1–D4; имена пока не заданы.
3. Согласовать [контракты данных](contracts/data.md), [исполнения](contracts/execution.md) и [API](contracts/api.md) до независимой разработки.
4. Принять/отклонить решения в [реестре](decisions.md); ответить на [вопросы](questions.md).
5. Каждый берёт свой модульный PRD и первые задачи. Интеграция начинается в первом рабочем интервале, не в конце хакатона.

## Важные ограничения

- Никакой стек не принят молча; названия каталогов обозначают ответственность, а не обязательные библиотеки.
- API v0 — предложение для параллельной работы; имена маршрутов и транспорта согласовать с репозиторием.
- Тестовые примеры/заглушки для UI обязаны быть помечены как fixtures. Они не считаются реальным расчётом, успешным check или мнением LLM.
- Данные, секреты и закрытые материалы организаторов не входят в этот пакет.
- ИИ/Codex: пользователь отложил интеграцию до самого конца; [поздний подмодуль](modules/05-ai-opinion.md), не пятая роль.
- Стенд: https://finance.corca.ru/ . При проверке корня показано только «Стенд готовится»; это не подтверждение API, БД, авторизации или работоспособности приложения.
- Пакет подготовлен в отдельной ветке репозитория как `docs/`; основной ветки не меняет до merge человеком-интегратором. [Существующее ядро и стыки](implementation-status.md) учитывать до выдачи задач, чтобы не дублировать уже начатую работу.
