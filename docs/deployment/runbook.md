# Стенд и ввод в эксплуатацию — проектный runbook

**Адрес:** https://finance.corca.ru/ . При публичном чтении корня получена страница «Хакатон МИФИ — система анализа изменений СПР. Стенд готовится». Ни API, ни runner, ни БД этим не проверены. Никаких изменений стенда в рамках docs PR не выполняется.

**Owner:** D2, deployment выполняет уполномоченный владельцем человек/агент. ОС, ресурсы, доступы, compose/services и способ reverse proxy пока неизвестны. Команды нельзя выдумывать под отсутствующий stack.

## До деплоя заполнить

- Подтверждённые ОС/CPU/RAM/disk и допустимая нагрузка.
- Release commit, команда сборки, команда тестов, команда старта/stop/restart и миграций.
- HTTP port приложения, reverse proxy path/base URL, health/readiness route.
- Persistence paths/volumes и права dataset read-only / run artifacts / DB.
- User-code trust mode, timeout/RAM/output limits, queue concurrency.
- Кто хранит секреты и выполняет deploy; не передавать их через Telegram/Git/frontend.
- Как сохранить данные и вернуться к предыдущему commit/release без переписывания Git history.

## Порядок — не автоматическое разрешение выполнить

1. Согласовать окно и owner, зафиксировать текущий release/config/data; backup при существующих данных.
2. На чистой среде собрать и выполнить tests по README. Никаких настоящих данных/secret fixtures в образе.
3. Подготовить storage/permissions и секреты отдельно; запустить выбранные сервисы.
4. Проверить health/readiness и затем настоящий browser smoke. 200 у корня заглушки не считается готовностью приложения.
5. Через https://finance.corca.ru/ создать Run, дождаться отчёта, открыть pivot и drill-down; скачать HTML и проверить абсолютный URL обратно в сводную.
6. Две независимые сессии, негативный user script, сохранность owner scopes и явная диагностика.
7. Записать release SHA, реальные проверки/вывод и ограничения; только после этого говорить «стенд готов».

Если smoke сломан — остановить rollout, вернуть последнюю проверенную версию по согласованной процедуре, проверить состояние данных. Никаких reset --hard/force push как метода production-отката.
